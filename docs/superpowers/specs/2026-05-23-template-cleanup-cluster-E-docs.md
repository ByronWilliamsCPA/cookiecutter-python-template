## Item 3: `qlty.yml` Workflow in Generated Project

### Gap

The generated project template is missing `qlty.yml`. The org standards manifest requires:
- **CI-013**: `qlty.yml` in expected workflow inventory
- **CI-004**: Qlty coverage workflow present

`{{cookiecutter.project_slug}}/.qlty/qlty.toml` already satisfies **TOOL-009** (present since before this cluster).

### File Location

`{{cookiecutter.project_slug}}/.github/workflows/qlty.yml` (new file)

### Content

Direct copy of the template repo's own `.github/workflows/qlty.yml`. No Jinja2 substitutions are needed — the file is plain YAML that works in any generated project:

```yaml
name: Qlty

on:
  workflow_run:
    workflows: ["CI"]
    types: [completed]

permissions: read-all

concurrency:
  group: qlty-coverage-${{ github.event.workflow_run.head_branch }}
  cancel-in-progress: true

jobs:
  qlty:
    if: ${{ github.event.workflow_run.conclusion == 'success' }}
    uses: ByronWilliamsCPA/.github/.github/workflows/python-qlty-coverage.yml@1b2d33c47cc11a96b9757b49f41873c54e75f57c  # main
    permissions:
      contents: read
      actions: read
    with:
      coverage-artifact-name: coverage-reports
      coverage-file-path: coverage.xml
      coverage-format: cobertura
      workflow-run-id: ${{ github.event.workflow_run.id }}
    secrets:
      QLTY_COVERAGE_TOKEN: ${{ secrets.QLTY_COVERAGE_TOKEN }}
```

The `workflow_run: ["CI"]` trigger matches the generated project's CI workflow (`name: CI` in `ci.yml`).

### Conditional Inclusion

`qlty.yml` is added to the per-feature cleanup list in `cleanup_conditional_files.py` under the `include_github_actions` guard, matching the pattern used by all other workflow files. When `include_github_actions == "no"`, the post-gen hook removes it.

### SHA Pin

Inherits the same SHA (`1b2d33c47cc11a96b9757b49f41873c54e75f57c`) already in use by the template repo itself. No new pinning work required for this cluster.

## Item 4: `PROJECT_SETUP.md` Qlty Documentation

### Location

`{{cookiecutter.project_slug}}/docs/PROJECT_SETUP.md` — two additions within the existing CI/CD section.

### Addition 1: Required Secrets Table

Add `QLTY_COVERAGE_TOKEN` to the existing `### Required GitHub Secrets` table (around line 422):

| Secret | Required by | Purpose |
|---|---|---|
| `QLTY_COVERAGE_TOKEN` | `qlty.yml` | Uploads coverage reports to Qlty for code quality metrics |

### Addition 2: Qlty Code Quality Subsection

Add `### Qlty Code Quality` immediately after the Core Workflows table, inside the existing `{%- if cookiecutter.include_github_actions == "yes" %}` block that already wraps that section. No new Jinja2 conditional is needed — the subsection inherits the parent guard.

Content covers:

**What Qlty does**: aggregates code quality metrics — complexity scores, code smell detection, and coverage trends — and surfaces them as PR comments via the `qlty.yml` workflow.

**What Qlty does not do**: it does not replace Ruff, BasedPyright, or pytest. Those run directly in CI; Qlty consumes their output to build trend data.

**Setup steps**:
1. Create a project at qlty.sh and link your GitHub repository
2. Copy the `QLTY_COVERAGE_TOKEN` from the Qlty project settings
3. Add it as a repository secret named `QLTY_COVERAGE_TOKEN`

**Configuration**: the `.qlty/qlty.toml` config is already generated — no manual configuration required.
